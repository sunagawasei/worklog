# worklogの稼働記録

## 操作元

worklog CLIと稼働記録ファイルの操作は、このworklogプロジェクトの管理元セッションだけで行う。
他プロジェクトやhandoff先では操作せず、対象タスクと開始・終了時刻を管理元へ報告する。
他workspaceから作業ディレクトリだけを変更して操作しない。
委譲先への依頼には二重記録しないことを明記する。

CLIは常に `--json` を付ける。
コマンドの仕様は [worklog-operation](../worklog-operation/SKILL.md)、過去タスクの検索は [worklog-find](../worklog-find/SKILL.md) を参照する。

## start [作業内容]

作業内容を省略した場合は、本人が着手を指示したタスクを使う。
計画の相談や候補の提示だけでは開始しない。
本人が記録不要と指定した作業は記録しない。
workspaceの起動後に本人からの資料を待つだけなら、実作業の開始と扱わない。資料を受け取って作業を始めた時刻を記録の起点にする。

1. `worklog status --json` で現在の計測を確認する。`new` と `switch` は別タスクを自動停止するため、別の並行作業を勝手に止めない。
2. 本人が指定した開始時刻を優先し、指定がなければ着手指示を受けた時刻をJSTの `HH:MM` で渡す。会話のタイムスタンプを確認できない場合は受信時点の現在時刻を記録し、長い調査後の実行時刻で代用しない。
3. Issue番号、チケットIDや固有名詞で過去タスクを検索する。検索対象はログのファイル名で、複数語は個別に検索して統合する。

   ```sh
   .claude/scripts/find-past-project.sh "<keyword>"
   worklog tag list --json
   ```

4. 同一タスクなら既存名と最終タグをそのまま使い、再確認しない。類似候補しかなければ上位3件と新規作成を示し、本人に一問ずつ確認する。
5. `worklog new --json "<プロジェクト名>" <タグID> <HH:MM>` で開始する。
6. `worklog status --json` で名前、タグと開始時刻を確認して報告する。別タスクを停止した場合は `prev_project` も報告する。

新規タスクは以下に従う。

- GitHub Issueが起点なら実際のタイトルを取得し、`#<番号> <タイトル>` とする。URLスラッグで命名しない。
- `worklog tag list --json` と同じ案件の直近タスクを根拠に名前とタグを提案する。本人の指定や同一タスクの記録で確定できない場合だけ確認する。
- 名前の禁止文字や長さの制限はworklog-operationに従う。

## stop [HH:MM]

本人が停止を明示したときだけ実行する。
workspace終了、wrapup、個別作業の完了報告だけでは停止しない。

`worklog stop --json [HH:MM]` で停止する。
過去の終了時刻が指定された場合はその時刻を渡す。
画像から読み取った時刻は本人に確認してから使う。
実行後にstatusとtimelineを確認し、終了時刻と区間を報告する。

## 遡及登録と訂正

カレンダーの予定を実際の参加時間と扱わず、本人報告などで実績の開始・終了時刻を確認する。
本人がセッション履歴からの計測を求めたら、資料受領や具体的な作業指示から成果保存の完了までを発言と応答の時刻で照合する。workspace準備、資料待ち、成果保存後の管理処理やwrapupを実作業時間へ含めない。途中の検討時間を、エージェントが応答していないという理由だけで差し引かない。履歴で判断できない中断だけ本人へ確認する。
現在の計測を変えないため、過去分の追加に `new`、`switch`、`stop` を流用しない。

現行CLIが追加・編集を扱えるかヘルプを確認する。
ファイル編集が必要なら対象日のログだけを変更し、既存ファイルは上書きしないバックアップを取る。
データの場所は `WORKLOG_DATA_DIR`、`XDG_STATE_HOME/worklog`、既定の `~/.local/state/worklog` の順に解決する。

ログは `YYYY/MM/DD/<プロジェクト名>.log` に次の形式で置く。

```text
YYYY/MM/DD HH:MM:SS<TAB>start|stop<TAB>タグID
```

誤った開始・停止行の修正やプロジェクト名の変更は、既存区間と重複を確認して行う。
`current` は稼働中のプロジェクト名を変える場合以外は変更しない。
変更後に `worklog timeline --json <YYYY-MM-DD>` で時刻、合計と重複を確認し、statusで現在の計測状態も照合する。
